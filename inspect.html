04 / Fingerprints for comparison

SHA-256 hashes of normalized sets of properties. Time, IP, events, cookies, and the random run ID are excluded. The hash changes whenever any included value changes. This is a configuration fingerprint, not a unique user ID.

Calculated after the main checks…

Environment: UA, platform, languages, timezone, CPU, memory, screen, and touch. Rendering: GPU and estimated font availability. Extended: Canvas and Audio, after extended checks have run. Window size is excluded, but screen dimensions and DPR are included in environment. Compare matching groups and algorithm versions. Unsupported fields make fingerprints less distinctive.

These are fetch requests, not top-level navigations. Accept, Origin, Sec-Fetch-* and Client Hints may differ. The Client Hints endpoint requests hints through a redirect, but hints may remain limited by browser policy for cross-origin fetch. Signature headers are only observations: this page does not verify signatures.

A failed fetch may mean CORS, CSP, a client or network block, DNS, or TLS failure. JavaScript usually cannot distinguish these causes or read a blocked response. A BLOCKED_BY_CLIENT message seen in browser tools cannot be inferred from TypeError alone. Open DevTools for the exact browser diagnostic. Echo services may add or normalize headers.

Endpoint contract and limitations

The GET endpoint returns the JSON below with Content-Type: application/json and Cache-Control: no-store. Reflect only allowed fields from the current request to the endpoint. Do not return Cookie, Authorization, or other secrets. Get the source IP from trusted CDN metadata, not an arbitrary X-Forwarded-For header. This page does not send the report to the endpoint.

{
  "observedAt": "ISO timestamp",
  "requestKind": "fetch",
  "headers": {

    "signature-agent": "...",
    "signature-input": "...",
    "signature": "...",
    "sec-ch-ua": "...",
    "sec-fetch-site": "same-origin"
  },
  "ip": "optional source IP",
  "asn": "optional edge enrichment",
  "verification": {
    "status": "not_checked",
    "provider": null,
    "method": null
  }
}

This response describes the fetch request, not the original navigation. To compare them, record navigation headers separately at the edge and link the requests with your own request/session ID. Signature-Agent alone does not confirm the provider without signature verification. The verification field must come from a real server-side verifier; this interface only displays its response.

These checkboxes are set manually and are not automatic verification results. A TLS/HTTP fingerprint describes the client stack, not the LLM in use.

How to compare results
  1. Open over HTTPS, label the baseline, and download the JSON after completing the steps.
  2. Ask each agent to open this URL in a browser, complete the steps, and download or copy the JSON. A text fetch may not execute JavaScript at all.
  3. If the agent cannot download a file, ask it to copy the full report from the final section.
  4. Repeat in fresh sessions. Matching Canvas/GPU/viewport values may suggest a similar environment image but do not prove the provider.
  5. Keep verified identity, automation signals, and general environment properties separate. Do not combine them into an “AI percentage”.
